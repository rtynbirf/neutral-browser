# E2E «не звонит домой» — протокол сертификата молчания (П43)

П43 (issue #2): НЕЙТРАЛЬНЫЙ БРАУЗЕР ПОЛЬЗОВАТЕЛЯ обещает не звонить домой —
пусть докажет строкой, не словом. Документ фиксирует протокол доказательства
и его уровни. Каждое утверждение подтверждается машинным выводом, а не
обещанием (правило README).

## 1. Что именно утверждается

1. Единственный сетевой путь в коде — `std::net::TcpStream` в `src/network.rs`
   (единственный модуль с правом I/O, закреплено гейтом `tests/architecture.py`).
2. Соединение открывается ТОЛЬКО по явной команде пользователя `--fetch`;
   фоновой загрузки, превы, телеметрии нет по построению.
3. Схема — только `http` (иначе `UNSUPPORTED_SCHEME`); HTTPS-канал «домой»
   в принципе невозможен, TLS-стека в дереве нет.
4. Хост соединения — только хост из пользовательского URL (capability
   наследуется от запроса, `BROKER_DENIED` для всего остального).
5. Процессы не порождаются — обходной канал «позвонить домой через curl»
   закрыт статически.

## 2. Уровень 0 — статика (offline, std-only Python)

`tools/silence_scan.py` — сканер молчания. Чеки fail-closed:

| Чек | Что гарантирует |
|---|---|
| S0_SRC_PRESENT | дерево `src/` на месте |
| S1_SOCKETS_CONFINED | примитивы `std::net` (TcpStream/UdpSocket/ToSocketAddrs) только в `network.rs` |
| S2_NO_NET_CRATES | сторонние сетевые крейты (reqwest/hyper/openssl/…) не упоминаются в коде |
| S3_NO_PROCESS_SPAWN | `Command::new`/`process::Command`/`spawn(`/`exec(` отсутствуют |
| S4A_BLOCKLIST_ZERO | телеметрийный блок-лист (analytics/ads/crash/metrica) — ноль вхождений во всём репо, включая доки и CI |
| S4B_SRC_EXTERNAL_HOSTS | в `src/` нет внешних хостов — только 127.0.0.1 и RFC 2606/6761 (*.test, example.*) |
| S4C_INVENTORY_ONLY_INFO | внешние URL в доках — цитаты-справки, учитываются отдельно как inventory |
| S5_CARGO_AUDIT | cargo-аудит (см. §4): `[dependencies]` пуст, lock ровно 1 пакет без checksum, версия лока = версии пакета |
| S6_PYLOOP_STD_ONLY | петля верификации (tools/tests *.py) импортирует только stdlib |

Машинные маркеры: последняя строка прогона — `SILENCE=PASS` (или `SILENCE=FAIL`,
exit 1). Каждое изменение дерева воспроизводимо перепрогоном за секунды.

**Негативная приёмка (обязательна):** `python3 tools/silence_scan.py --selftest`
строит фикстуры-нарушения (TcpStream вне network.rs, reqwest, spawn, внешний
beacon-хост в src/, телеметрийный URL в доке, зависимость в Cargo.toml,
устаревший lock, non-stdlib import) и требует, чтобы КАЖДАЯ дала красный.
Нарушенный блок-лист в тесте = красный — это машинная приёмка негатива
(`SELFTEST=PASS` фиксирует, что красный действительно загорается).

## 3. Уровень 1 — живой e2e «сертификат молчания»

CI (`.github/workflows/ci.yml`, шаг «E2E сертификат молчания») наrunner с
Rust-тулчейном:

1. `cargo build --locked --all-targets` — сборка по фиксации зависимостей.
2. `python3 tests/architecture.py` — архитектурный гейт (включая
   `cargo check --locked` внутри).
3. `python3 tools/silence_scan.py --selftest` + `python3 tools/silence_scan.py`
   — негатив и статика.
4. `./target/debug/neutral-browser --self-test` — встроенный самотест бинарника.
5. `python3 tools/e2e.py` — живой прогон: поднимает локальный HTTP-сервер на
   127.0.0.1, ведёт РЕАЛЬНЫЙ бинарник по контрактам стадий 2–9, сверяет
   машинный вывод построчно. Внешняя сеть не нужна — весь трафик замыкается
   на loopback, что и есть «не звонит домой» в действии.

### 3.1. Уровень 1.5 — runtime-детектор внеполосных попыток (волна ×6)

`tools/silence_e2e.py` — «сертификат молчания» для СОБРАННОГО бинарника.
Детектор сетевых попыток перехватывает connect/sendto/sendmsg и утверждает:
**ноль внеполосных обращений** — то есть ноль попыток дотянуться до любого
адреса, кроме явно разрешённого приёмкой списка (зелёный прогон: только
`127.0.0.1:<порт тест-сервера>`). Любая попытка вне списка = красный,
fail-closed (`SILENCE_E2E=FAIL`, exit 1).

Детекторы (выбор честно печатается маркером `DETECTOR=`):

| Ярус | Механизм | Что видит |
|---|---|---|
| `strace` | ptrace-трасса syscall'ов connect/sendto/sendmsg | ЛЮБЫЕ попытки, включая сырые syscall'ы мимо libc (приоритетный ярус CI) |
| `ldpreload` | LD_PRELOAD-шим: интерпозиция libc (C-исходник компилируется `cc` из встроенного текста) | все вызовы через libc; фолбэк там, где ptrace недоступен |
| `none` | — | сертификат НЕ выдаётся: `SILENCE_E2E=NOT_ISSUED`, exit 2 (fail-closed — без детектора свидетельство молчания ложно) |

Приёмки церемонии (каждая — машинная):

| Маркер | Приёмка |
|---|---|
| `LEAK_PROBE=CAUGHT` | «нарушитель» — отдельный бинарник (Rust-профиль тот же, что у движка; фолбэк std-only Python), который стучится на известный адрес RFC 5737 TEST-NET-1 — ОБЯЗАН быть пойман. Детектор, пропустивший нарушителя, порочен — сертификат не выдаётся |
| `CLEAN_PROBE=PASS` | тот же зонд на loopback обязан быть чистым (двухсторонний контроль: детектор не «красит всё подряд») |
| `LOOPBACK_FETCH=PASS` | реальный движок: fetch loopback-страницы через брокер, `FETCH=OK` + `BODY_SHA256` страницы, ноль внеполосных попыток (`CONNECT_LOOPBACK=1`, `LOOPBACK_VIOLATIONS=0`) |
| `BLOCKED_ADDR=CAUGHT` | негатив П43: движок с ПУСТЫМ разрешённым списком тянется к известному адресу — попытка ОБЯЗАНА быть поймана детектором, а движок честно отчитывается `ERROR_KIND=CONNECT` (rc 5). Это и есть «режим, который разрешает известный адрес, — тест ловит его как нарушение» |
| `NETNS=ON` + `NETNS_GREEN/NETNS_BLOCKED` | строгий сетевой namespace `unshare` (только loopback, снаружи физически ничего не открыть): та же приёмка повторяется внутри — попытка фиксировалась детектором и там |

Машинные маркеры: детектор (`DETECTOR=strace|ldpreload`), ярус netns
(`NETNS=ON|OFF`), счётчики (`CONNECT_LOOPBACK`, `LOOPBACK_VIOLATIONS`),
итог `SILENCE_E2E=PASS|FAIL|NOT_ISSUED` (exit 0/1/2). Ручной протокол
блок-листа nftables (§3 ниже) остаётся опциональным для доверенной машины.

`python3 tools/silence_e2e.py --selftest` — негативная приёмка самого
детектора: юнит-чеки парсера/классификатора (синтетические строки strace:
loopback-разрешено, внешнее-нарушение, IPv6, v4-mapped, AF_UNIX/AF_NETLINK,
неразобранная INET-строка = нарушение) + живой двухсторонний негатив
(`LEAK_PROBE=CAUGHT`, `CLEAN_PROBE=PASS`) + сборка шима
(`SHIM_BUILD=PASS`). Итог — `SELFTEST=PASS` (exit 0).

### Ручной протокол блок-листа (доверенная машина, вне CI)

```
# разрешён только loopback, всё остальное — drop (пример nftables):
nft add table inet silence
nft add chain inet silence out '{ type filter hook output priority 0; policy accept; }'
nft add rule inet silence out oif != "lo" ip daddr != 127.0.0.1 counter drop
./target/debug/neutral-browser --fetch http://127.0.0.1:18080/index.html --dom
# критерий: страница собрана, счётчик drop-пакетов не вырос ни на один
# внеполосный пакет. Любой пакет наружу от имени браузера = красный.
```

Негативный вариант: поднять фейковый телеметрийный эндпоинт и подложить его
URL в исходник — сканер обязан дать красный (эквивалент покрыт selftest-фикстурой).

## 4. Cargo-аудит: оффлайн-эквивалент S5 + внешние CI-аудиторы (волна ×6)

Оффлайн-петля верификации (tests/architecture.py, tools/*.py) остаётся
std-only: cargo-deny/cargo-audit не входят в неё — это решение REJECTED
зафиксировано в tests/architecture.py. Эквивалент deny-чеков внутри
оффлайн-петли — чек S5:

- `[dependencies]` пуст строго (ни одной строки, кроме заголовка);
- нет `[dev-dependencies]` / `[build-dependencies]` / `[patch]` / `[features]` / `[target.*]`;
- `Cargo.lock` содержит ровно один пакет (neutral-browser) и ни одного
  `checksum` (содержимое сторонних крейтов всегда несёт checksum — его
  отсутствие доказывает пустоту графа зависимостей на уровне лока);
- версия лока = версии пакета (храповик против устаревшего лока; устаревший
  lock ломал бы `cargo check --locked`).

Пустое множество зависимостей ⇒ пустое множество крейтов ⇒ нечему
конфликтовать (дубликаты), нечему быть уязвимым (advisories), нет лицензий
крейтов для проверки. Это и есть deny-чеки для множества мощности ноль.

**Волна ×6 (П43 #2): внешние CI-аудиторы добавлены как второй контур.**
`.github/workflows/cargo-deny.yml` гоняет `cargo-deny check
(licenses/advisories/bans/sources)` + `cargo-audit` по `Cargo.lock`
(еженедельно + на каждый пуш/PR). Границы честности:

- это НЕ зависимости движка и НЕ часть оффлайн-петли: граф по-прежнему
  пуст, `deny.toml` обслуживает только внешний прогон;
- тулы ставятся из официальных релизов GitHub с пломбой sha256 тарболла
  (версия+хеш вписаны в workflow — никакого плавающего latest);
- первая настоящая зависимость обязана пройти licenses/bans/advisories в
  deny.toml И сломать S5 (он требует пустоту) — то есть стать
  осознанным изменением политики, а не тихим проскоком.
